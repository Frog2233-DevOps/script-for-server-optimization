# Полная документация bootstrap.sh v1.2.0

> Документ разбирает скрипт построчно по блокам: что делает каждая часть,
> какие гарантии даёт и где проходят границы ответственности.
> Для краткого описания см. README.md, для аудиторов ИИ — docs/AI_AUDIT_CONTEXT.md.

---

## 1. Назначение и философия

Скрипт — **bootstrap/hardening** для свежего Ubuntu-сервера (24.04/26.04).
Философия: после одного запуска сервер должен быть готов к работе и при этом
невозможно залочить себя снаружи. Все решения подчинены трём приоритетам:

1. **Не потерять доступ** (любой сбой на SSH-шаге откатывается);
2. **Не оставить дыр** (пароли и root закрываются только после проверки ключей);
3. **Повторный запуск безопасен** (идемпотентность).

---

## 2. Архитектура: карта выполнения

```
┌─────────────────────────────────────────────────────────────┐
│ 0. Проверки окружения (НИЧЕГО не меняет в системе)          │
│ 1. Сбор и валидация SSH-ключей                              │
│ 2. Обновление системы (+ восстановление dpkg)               │
│ 3. Базовые пакеты + автоматические security-обновления      │
│ 4. Hostname / timezone / NTP                                │
│ 5. Пользователь, ключи, sudo, блокировка root               │
│ 6. UFW (firewall)                                           │
│ 7. fail2ban                                                 │
│ 8. sysctl: BBR + сеть                                       │
│ 9. Лимиты, journald, logrotate                              │
│ 10. Swap                                                    │
│ 11. Docker (опционально)                                    │
│ 12. SSH-харденинг в ТРАНЗАКЦИИ с автоматическим откатом     │
└─────────────────────────────────────────────────────────────┘
```

Ключевая идея порядка: **всё, что может отрезать доступ (шаги 6, 12),
выполняется после того, как новый доступ (пользователь + ключи) уже создан и
проверен на конфигурационном уровне**.

### Система защиты от локаута (три независимых механизма)

| Механизм | Где | Что гарантирует |
|---|---|---|
| `SSH_TXN` + `rollback_ssh` + `trap on_exit` | шаг 12 | Любой выход со сбоем после начала правки sshd восстанавливает прежние drop-in'ы и перезапускает ssh |
| Переходные порты в UFW | шаг 6 | Прежние порты SSH остаются открытыми, пока новый порт не поднят и не проверен |
| `sshd -t` + `sshd -T` до перезапуска | шаг 12 | Перезапуск происходит только если эффективный конфиг содержит ровно ожидаемые значения |

## 3. Разбор по блокам

### 3.0. Заголовок и режимы запуска

```bash
set -Eeuo pipefail
umask 022
```

- `-E` — trap ERR наследуется функциями (важно: `die` срабатывает внутри функций);
- `-e` — выход при первой ошибке;
- `-u` — ошибка при обращении к несуществующей переменной;
- `-o pipefail` — падение любой команды в пайплайне = падение пайплайна.

Парсинг аргументов — классический `while/case` с `${2:?}` (обязательный аргумент).
Неизвестный флаг → usage на stderr + exit 2.

### 3.1. Root, лог, блокировка, временные файлы

- Проверка `EUID -eq 0` до любых изменений.
- Лог `/var/log/bootstrap.log` (права 600) через `exec > >(tee -a ...) 2>&1` —
  дублирование stdout/stderr в лог и на экран.
- **Lock-файл `/run/bootstrap.lock`** через `flock -n 9` — второй параллельный
  запуск отклоняется. `/run` — tmpfs, лок сбрасывается перезагрузкой.
- `WORKDIR=$(mktemp -d)` — все временные файлы в одном месте, `trap on_exit`
  гарантирует удаление при любом выходе.
- Три trap:
  - `EXIT` → `on_exit` (откат SSH + очистка WORKDIR);
  - `INT TERM` → `die "Прервано сигналом"` (Ctrl+C тоже инициирует откат SSH);
  - `ERR` → сообщение с `$LINENO` и `$BASH_COMMAND` — мгновенная диагностика.

### 3.2. Утилиты

- **`apt_run`** — `apt-get` с флагами: неинтерактивный режим, `confdef/confold`
  (конфликты конфигов решаются без вопросов), `DPkg::Lock::Timeout=600`
  (ожидание освобождения dpkg, который на свежем VPS часто занят apt-daily
  первые минуты), `Acquire::Retries=3`.
- **`apt_install`** — устанавливает только пакеты, реально существующие в
  архиве (`apt-cache show`), остальные пропускает с предупреждением.
  **Используется ТОЛЬКО для необязательных пакетов** — обязательные ставятся
  через `apt_run`, чтобы их отсутствие привело к падению, а не к тихому пропуску.
- **`backup_file`** — копия изменяемого файла в `/var/backups/bootstrap/<дата>/`
  (каталог 700) с заменой `/` на `_` в имени.
- **`write_file`** — запись файла **только если содержимое изменилось**
  (`cmp -s`), со старой копией в бэкап. Идемпотентность всей конфигурации
  держится на этой функции.
- **`ufw_allow`** (добавлено в v1.2.0) — идемпотентное открытие порта:
  проверяет `ufw status` перед добавлением (сам ufw дубли не дедуплицирует).
- **`detect_ssh_ports`** — собирает все порты, на которых SSH доступен
  **прямо сейчас**: `sshd -T`, прослушивание `ssh.socket`, порт текущей
  сессии (`$SSH_CONNECTION`). Нужно, чтобы UFW не закрыл вход раньше времени.

### 3.3. Шаг 0/12 — проверки (до первого изменения системы)

Принцип: **вся валидация до любой мутации**, чтобы не падать посреди настройки.

- ОС = Ubuntu, версия 24.04/26.04 (иначе exit; `--force` — на свой риск);
- имя пользователя: `^[a-z_][a-z0-9_-]{0,31}$`, не root;
- порт SSH: 1–65535, нормализация `10#` (защита от ведущих нулей);
- swap: `0` или `<число>M/G`;
- `--ports`: одиночные порты, диапазоны только с явным протоколом;
- таймзона существует в `/usr/share/zoneinfo`;
- hostname проходит regex;
- если пользователь уже существует: запрет системных UID (<1000) и
  shell `nologin/false` без `--force` (не выдаём NOPASSWD-sudo системным
  аккаунтам вроде `www-data`);
- обнаружение контейнера (`systemd-detect-virt -c`) — swap/sysctl будут пропущены;
- свободное место на `/` ≥ 1536 МБ;
- резолв `archive.ubuntu.com` (warning, не die);
- доставка `iproute2`, если нет `ss`;
- определение socket-режима (`ssh.socket` enabled → `SOCKET_MODE=1`);
- **занятость нового порта** через `ss` (если порт уже слушает другой сервис — die);
- сбор текущих портов SSH в `OLD_SSH_PORTS`.

### 3.4. Шаг 1/12 — SSH-ключи

Источники ключей (объединяются): env `SSH_KEYS`, флаги `-k` (можно несколько),
`--keys-file`, `--github USER`, интерактивный ввод, fallback на
`/root/.ssh/authorized_keys`.

Защиты:

- Интерактив читает из `/dev/tty` (при `curl | bash` stdin занят самим скриптом);
- **отказ от приватных ключей** — по подстроке `PRIVATE KEY` (в prompt и финально);
- каждый ключ валидируется `ssh-keygen -l -f` (формат + отпечаток);
- дедупликация строк, удаление `` (вставка из Windows);
- пустой результат → `die` (без ключей пароли не отключаем — иначе локаут);
- **отпечатки всех ключей пишутся в лог** — администратор обязан сверить.

**v1.2.0 [FIX W1]**: при заборе ключей из `/root/.ssh/authorized_keys` срезаются
только опасные обёртки `command=` и `environment=` (у cloud-образов ключи root
обёрнуты в `command="...exit 142"` — такие новому пользователю нельзя), а
ограничения `from=` **сохраняются** — иначе ключ root, ограниченный по IP,
начал бы работать с любого адреса.

### 3.5. Шаг 2/12 — обновление системы

- **v1.2.0 [FIX W7]**: `dpkg --audit` → `dpkg --configure -a` — восстановление
  после жёсткого обрыва (SIGKILL/питание) посреди прошлого прогона.
  `Lock::Timeout` этого не лечит: он ждёт лок, а не чинит полунастроенные пакеты.
- `apt update` → `full-upgrade` (пропускается флагом `--no-upgrade`).
- `autoremove --purge` — только по явному флагу `--autoremove` (необратимо).

### 3.6. Шаг 3/12 — пакеты

- Обязательные через `apt_run` (падение = сбой): sudo, iproute2, openssh-server,
  ufw, fail2ban, python3-systemd, unattended-upgrades, ca-certificates, curl.
- Необязательные через `apt_install` (чего нет в релизе — пропускается).
- `/etc/apt/apt.conf.d/20auto-upgrades` — включены автообновления списков
  пакетов и unattended-upgrade (security-патчи ставятся сами).
- Отключение рекламы в motd/apt.

### 3.7. Шаг 4/12 — hostname и время

- `hostnamectl set-hostname` + `preserve_hostname: true` для cloud-init
  (иначе hostname вернулся бы из метаданных провайдера при перезагрузке).
- **v1.2.0 [FIX W6]**: запись `127.0.1.1 <hostname>` в /etc/hosts **заменяет**
  существующую строку вместо бесконечного дописывания при смене hostname.
- Таймзона (опционально), NTP через `timedatectl set-ntp true`.

### 3.8. Шаг 5/12 — пользователь, ключи, sudo

- Создание пользователя с bash и группой sudo (или переиспользование
  существующего — тогда `usermod -aG sudo`).
- `chmod go-w $U_HOME` — StrictModes: group/world-writable home отверг бы ключи sshd.
- `authorized_keys`: слияние существующих и новых ключей с дедупликацией,
  права **600, владелец пользователь** (иначе sshd файл проигнорирует).
- **sudo NOPASSWD через sudoers.d** (основной sudoers не трогается):
  правило проходит `visudo -cf` до установки, после установки полный
  `visudo -c` — если итоговая конфигурация сломана, правило удаляется.
  Добавление `@includedir /etc/sudoers.d`, если его нет.
  RISK (осознанный, в комментарии): компрометация ключа = root. Пароль для
  sudo задать некому (пароля у пользователя нет по дизайну).
- `passwd -l root` — блокировка пароля root (в т.ч. в VNC-консоли провайдера;
  отключается `--no-lock-root`).
- Опционально `umask 0077` в .bashrc (с проверкой на дубль).

### 3.9. Шаг 6/12 — UFW

- `default deny incoming` / `allow outgoing`.
- Порты SSH определяются заново (могли измениться после установки openssh-server).
- Открыт новый порт + **все прежние порты SSH как SSH-transition** — до тех пор,
  пока новый порт не поднят и не проверен вручную, вход сохраняется.
- **v1.2.0 [FIX W8]**: порт в `--ports` без протокола открывается как **только
  tcp** (vanilla `ufw allow 80` открыл бы и udp — шире, чем ожидает пользователь).
- `--block-ping`: DROP только IPv4 echo-request, остальной ICMP не трогается
  (иначе сломается PMTUD).
- Не включился (нет netfilter в контейнере) — warning, не die.

### 3.10. Шаг 7/12 — fail2ban

- `ignoreip`: loopback + IP текущей сессии (под `sudo -i` может потеряться —
  тогда просто не добавится, не критично).
- Нарастающий бан: increment, factor 2, max 1 неделя.
- Jail sshd: maxretry 5, findtime 10m, bantime 1h.
- **v1.2.0 [FIX W4]**: jail следит и за переходными портами (`port = 49500,22`),
  пока они открыты — перебор по прежнему порту тоже банится.
- Конфиг проверяется `fail2ban-client -t` до применения; после restart —
  не доверяем коду возврата (restart возвращает 0 даже при падении демона
  через 300 мс), проверяем `systemctl is-active` + `fail2ban-client ping`
  с задержкой 3 секунды.

### 3.11. Шаг 8/12 — sysctl (BBR + сеть)

- BBR включается только на VM (не в контейнере) и только если модуль доступен
  в ядре (`/proc/sys/net/ipv4/tcp_available_congestion_control`), с постоянной
  загрузкой модуля через modules-load.d.
- **Резервирование эфемерного порта** (`ip_local_reserved_ports`), если новый
  порт SSH попадает в диапазон 32768–60999 — исходящее соединение не займёт
  его раньше sshd. Существующий список дополняется, а не затирается.
- Комментарий фиксирует, что **сознательно НЕ включено**: overcommit_memory=2
  (ломает Docker/Redis/Node), ECN, фиксированные tcp_mem/udp_mem, TFO и т.п. —
  только безопасный подмножество «Linux-Optimizer».
- Применение через `sysctl -p` с `|| warn` — в контейнере часть параметров
  неприменима, это не критично.

### 3.12. Шаг 9/12 — лимиты, journald, logrotate

- nofile: soft 65536 / hard 1048576 (soft=1M ломал бы select() и fork;
  приложение поднимет soft сам, как и systemd по умолчанию).
- **journald Storage=persistent** — без него логи sshd/fail2ban пропадали бы
  после перезагрузки (Storage=auto не создаёт /var/log/journal).
- `daemon-reexec` / restart journald — только если файл реально изменился.
- logrotate для bootstrap.log: monthly, 6 ротаций, create 0600.

### 3.13. Шаг 10/12 — swap

- Атомарность: файл собирается как `/swapfile.bootstrap` и **переименовывается**
  только после `mkswap` — прерванный запуск не оставит битый активный swap.
- umask 077 + chmod 600. fstab-дубль проверяется grep'ом.
- Пропуски без сбоя: флаг 0, контейнер, swap уже есть, мало места,
  `/swapfile` существует, но не подключён.

### 3.14. Шаг 11/12 — Docker (опционально)

- `daemon.json` (ротация логов контейнеров) пишется **до** установки пакета:
  пакет стартует dockerd сразу, а работающий демон `--now` не перечитывает конфиг.
- Если docker уже работал и конфиг изменился — перезапуск с предупреждением.
- Предупреждения: Docker обходит UFW для `-p` портов; группа docker — после
  перелогина.

### 3.15. Шаг 12/12 — харденинг SSH (транзакция)

Многоуровневая защита:

1. **v1.2.0 [FIX W2]**: собираются все человеческие пользователи (UID 1000–65533)
   с рабочим shell и непустым authorized_keys — они добавляются в AllowUsers,
   иначе скрипт молча отрезал бы SSH-доступ существующим администраторам.
2. Проверка `Include /etc/ssh/sshd_config.d/` в sshd_config (добавление в
   начало файла при отсутствии, с бэкапом).
3. Снимок прежних drop-in'ов → `SSH_TXN=1` (с этого момента любой выход
   откатит конфиг).
4. Drop-in `00-bootstrap.conf` (префикс 00 — sshd берёт первое встреченное
   значение, мы перекрываем `50-cloud-init.conf` с PasswordAuthentication yes):
   - `Port` (если ≠ 22), `PermitRootLogin no`, `PasswordAuthentication no`,
     `KbdInteractiveAuthentication no`, `PermitEmptyPasswords no`;
   - `AuthenticationMethods publickey` — только ключ, без fallback;
   - `AllowUsers <список>`;
   - анти-перебор: MaxAuthTries 3, LoginGraceTime 30, MaxStartups 10:30:60;
   - сессии: ClientAliveInterval 60 / CountMax 5;
   - `LogLevel VERBOSE` (нужен fail2ban с backend=systemd);
   - отключены X11, agent forwarding; TCP forwarding — local only;
     GatewayPorts no; PermitTunnel no.
5. `sshd -t` → парсинг `sshd -T`:
   - каждое ожидаемое значение проверяется grep'ом;
   - **ровно одна** строка `allowusers` (другой drop-in мог бы молча расширить
     список допущенных пользователей — это проверка на такой сценарий);
   - authorized_keys непуст.
6. Ubuntu 24.04/26.04 — socket activation: порт задаёт `ssh.socket`, поэтому
   отдельный drop-in `zz-bootstrap-port.conf` с `ListenStream=` (сброс) +
   `ListenStream=<порт>`; restart ssh.socket + reload-or-restart ssh.
7. Цикл до 15 секунд: ждём, пока `ss` увидит прослушивание нового порта,
   иначе die → откат.
8. `SSH_TXN=0` — успех, откат больше не нужен.
9. **v1.2.0 [R1]**: ротация `/var/backups/bootstrap/` — остаются последние 10
   снапшотов.

Финальный блок: сводка состояния + **обязательные предупреждения**:
проверить вход в новом окне до закрытия сессии, закрыть переходные порты
(`ufw delete allow <старый>/tcp`), перезагрузка если требуется новое ядро.

## 4. Матрица безопасности

| Угроза | Защита в скрипте |
|---|---|
| Перебор паролей SSH | PasswordAuthentication no + AuthenticationMethods publickey + fail2ban (maxretry 5, растущий бан до недели) |
| Перебор по переходным портам | fail2ban следит за всеми открытыми SSH-портами [v1.2.0] |
| Вход root | PermitRootLogin no + `passwd -l root` |
| Компрометация обычного пользователя | sudo NOPASSWD = root (осознанный компромисс; ключ единственный секрет) |
| Утечка ключа с ограничением from= | from= сохраняется при переносе из root [v1.2.0] |
| Отрезание других админов | автообнаружение пользователей с ключами для AllowUsers [v1.2.0] |
| Локаут при сбое настройки SSH | транзакция SSH_TXN + rollback_ssh + переходные порты |
| Полунастроенный сервер после обрыва | dpkg --configure -a при повторном запуске [v1.2.0] |
| Дубли конфигов при повторном запуске | write_file (cmp перед записью), ufw_allow, замена 127.0.1.1 |
| Лишние открытые порты | default deny incoming; порты без протокола → только tcp [v1.2.0] |
| Устаревшие пакеты | unattended-upgrades (security-патчи автоматически) |
| Потеря логов после ребута | journald Storage=persistent |
| Засорение диска логами | logrotate: bootstrap.log monthly/6, journald SystemMaxUse=500M, docker log-opts |
| Невалидные/приватные ключи | ssh-keygen -l валидация, отказ от "PRIVATE KEY" |
| Порт SSH занят другим сервисом | проверка ss до изменений |
| Смена hostname облачным провайдером | preserve_hostname для cloud-init |

### Остаточные риски (честный список)

1. **«Валидный, но чужой» ключ** — скрипт не может проверить, что у тебя есть
   приватная пара. Единственная защита: сверка отпечатков + наличие
   консоли/rescue у провайдера. Двухфазный режим (--stage-keys/--finalize)
   в roadmap.
2. **NOPASSWD sudo** — украденный ключ = мгновенный root. Плата за отсутствие
   пароля у пользователя.
3. **kernel.panic=10** — на железном сервере без kdump повторяющаяся паника
   даст boot loop (диагностика потеряется). Рассмотреть kdump.
4. **Docker обходит UFW** для опубликованных `-p` портов — это свойство Docker,
   не скрипта (предупреждение выводится).
5. **Ключи с GitHub (--github)** доверяются полностью — кто контролирует
   аккаунт, тот получает root. В README и в скрипте — обязательная сверка
   отпечатков.

## 5. Идемпотентность: как это обеспечивается

| Механизм | Где |
|---|---|
| `write_file` (cmp перед записью, флаг WRITE_CHANGED) | все конфиги через него |

## 6. Требования к окружению

- Ubuntu 24.04 / 26.04 (проверяется, `--force` для остального);
- root (проверяется);
- systemd (без него часть шагов пропускается с warning — работа в chroot/
  контейнере возможна, но не является целевым сценарием);
- ≥ 1.5 ГБ на /; рабочий DNS и доступ к зеркалам apt;
- bash ≥ 5 (используются `mapfile`, `BASH_REMATCH`, массивы с `set -u`).
