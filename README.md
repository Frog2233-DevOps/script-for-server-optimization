# script-for-server-optimization

Однокомандная первичная настройка (bootstrap / hardening) свежего Ubuntu-сервера
**24.04 / 26.04**: пользователь с SSH-ключами, sudo, UFW, fail2ban, BBR, swap,
автообновления безопасности, journald/logrotate, опционально Docker.

Версия скрипта: **v1.2.0** (два независимых аудита, см. историю версий ниже).

---

## 🚀 Быстрый старт — одна команда

От root на свежем сервере (`sudo -i`, затем):

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/ВАШ_ЛОГИН/ВАШ_РЕПОЗИТОРИЙ/main/bootstrap.sh)
```

Скрипт сам спросит публичный ключ в терминале.

**Вариант без вопросов** (передать ключ сразу):

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/ВАШ_ЛОГИН/ВАШ_РЕПОЗИТОРИЙ/main/bootstrap.sh)   --key "ssh-ed25519 AAAA... ваш_публичный_ключ"
```

или взять ключи с GitHub-аккаунта:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/ВАШ_ЛОГИН/ВАШ_РЕПОЗИТОРИЙ/main/bootstrap.sh) --github ВАШ_НИК
```

> ⚠️ **Перед запуском убедись, что есть доступ к консоли/rescue-режиму провайдера.**
> Скрипт отключает вход по паролю и root по SSH. Проверь отпечатки ключей,
> которые он выведет, до закрытия текущей сессии.

## 🔒 Для production: закрепи на коммит

Вместо `main` указывай конкретный коммит или тег и сверяй sha256:

```bash
# 1. Посмотри хеш коммита на GitHub (кнопка <> Code → копируй полный SHA)
# 2. Сверь контрольную сумму файла с тем, что в релизе репозитория
curl -fsSL https://raw.githubusercontent.com/ВАШ_ЛОГИН/ВАШ_РЕПОЗИТОРИЙ/<ПОЛНЫЙ_SHA_КОММИТА>/bootstrap.sh -o bootstrap.sh
echo "adee7d3951542eab27003d0d5f7fe7fc031ab4af6894d5bdaa038e64bb8a5a79  bootstrap.sh" | sha256sum -c
# 3. Только после OK — запуск
bash bootstrap.sh
```

## 📋 Что делает скрипт

| Шаг | Действие |
|---|---|
| 0 | Проверки: ОС, root, место на диске, занятость порта, валидация всех аргументов |
| 1 | Сбор и валидация SSH-ключей (проверка отпечатков, отказ от приватных ключей) |
| 2 | Обновление системы (full-upgrade), восстановление полунастроенного dpkg |
| 3 | Базовые пакеты, включены автообновления безопасности |
| 4 | Hostname, /etc/hosts, таймзона, NTP |
| 5 | Пользователь с sudo NOPASSWD, authorized_keys 600, блокировка пароля root |
| 6 | UFW: default deny, открыт новый порт SSH + переходные порты |
| 7 | fail2ban с нарастающим баном, следит и за переходными портами |
| 8 | BBR + консервативный sysctl (безопасные значения) |
| 9 | Лимиты файловых дескрипторов, постоянный journald, logrotate |
| 10 | Swap-файл (атомарное создание, не ломается при прерывании) |
| 11 | Опционально Docker (флаг `--docker`) |
| 12 | Харденинг SSH в транзакции с автоматическим откатом |

**Гарантии от локаута:** UFW включается до смены порта SSH, прежние порты
остаются открытыми до проверки, любой сбой на шаге 12 откатывает sshd-конфиг
через trap, эффективный конфиг проверяется `sshd -T` до перезапуска.

## ⚙️ Основные параметры

```text
-u, --user NAME      пользователь (default: super)
-p, --ssh-port N     порт SSH (default: 49500)
    --ports "LIST"   доп. порты ufw, напр. "80/tcp 443/tcp 6000:6010/tcp"
    --swap SIZE      512M / 2G / 0=выключить (default: 2G)
    --timezone TZ    напр. Europe/Moscow
    --hostname NAME  сменить hostname
    --packages LIST  доп. пакеты apt
    --docker         установить Docker
    --block-ping     не отвечать на ping
    --no-upgrade     пропустить full-upgrade
    --no-lock-root   не блокировать пароль root
    --reboot         перезагрузка через 1 минуту в конце
    --force          игнорировать проверку версии Ubuntu
```

## 🧪 Тестирование

Перед продом прогони на тестовом VPS:

```bash
# повторный запуск
bash bootstrap.sh
# прерывание на середине (Ctrl+C во время apt) и повторный запуск
# проверка из нового окна:
ssh -p 49500 super@IP && sudo -n true
```

## 📝 История версий

- **v1.2.0** — второй аудит: сохранение `from=` у ключей, не отрезаем других
  администраторов (AllowUsers), fail2ban на переходных портах, идемпотентный
  UFW, `dpkg --configure -a`, ротация бэкапов, порты без протокола → только tcp.
- **v1.1.0** — первый независимый аудит: транзакционный откат SSH, write_file,
  валидация аргументов до изменений системы.
